# SQL 与 SQL 注入系统教程

这套教程面向希望从 SQL 基础学到 SQL 注入原理、授权测试和防御验证的学习者。内容按依赖关系拆成四章：先理解数据库如何解释 SQL，再研究输入如何改变语句结构，之后学习 sqlmap 如何自动完成相同的判断，最后回到工程防御和回归测试。

## 使用边界

所有注入请求、payload 和 sqlmap 命令只允许用于以下环境：

1. 你自己编写并在本机运行的实验程序；
2. 明确标注允许此类测试的教学靶场；
3. 资产所有者书面授权、且范围和时间窗口明确的测试系统。

不要把示例域名替换成随机网站。教程不包含删除数据、写入服务器文件、获取系统 Shell、持久化、隐藏痕迹或扩大控制范围的操作。学习目标是理解、验证和修复漏洞，不是破坏系统。

## 推荐学习方法

每个知识点依次完成四件事：

1. 在数据库客户端中手写正常 SQL，确认结果；
2. 把 SQL 放入本地实验程序，观察应用怎样构造查询；
3. 在本地靶场中用最小、无破坏性的输入验证结构是否可控；
4. 改成参数化查询并添加回归测试，确认同一输入只被当成普通数据。

不要一开始就背 payload 或 sqlmap 参数。payload 只是“闭合原上下文 + 插入新表达式 + 处理剩余语句”的具体表现；理解数据库最终收到的完整 SQL，才能处理不同语言、驱动和数据库方言。

## 示例数据模型

四章统一使用一个小型商城模型：

```text
users 1 ----- n orders 1 ----- n order_items n ----- 1 products
```

- `users`：用户与角色；
- `products`：商品与价格；
- `orders`：订单及所属用户；
- `order_items`：订单和商品的多对多关联。

教程中的 `training_flag`、测试账号和商品均是假数据。不要在练习库中放真实密码、Cookie、令牌或个人信息。

## 方言约定

主要示例尽量使用标准 SQL，并指出 MySQL、PostgreSQL、SQL Server 和 SQLite 的常见差异。除非特别说明：

- 字符串使用单引号：`'alice'`；
- 标识符不加引号；确需引用时，各数据库可能使用 `"name"`、反引号或方括号；
- `-- ` 表示单行注释时，双减号后保留一个空格；
- 示例中的分页默认写作 `LIMIT ... OFFSET ...`；SQL Server 通常使用 `OFFSET ... FETCH`；
- 参数占位符只表示“由驱动绑定参数”，实际写法可能是 `?`、`%s`、`:name` 或 `$1`。

## 完成标准

学完后应当能够：

- 独立编写常用 CRUD、JOIN、聚合、子查询、CTE 和事务；
- 看到应用代码时判断输入进入了值、标识符还是语法片段；
- 解释联合、报错、布尔盲注、时间盲注、堆叠和二次注入的成立条件；
- 在本地或授权靶场中控制 sqlmap 的目标、参数、技术类型和请求强度；
- 使用参数化查询、白名单、最小权限和安全错误处理完成修复；
- 为历史漏洞建立可以自动执行的回归测试。
